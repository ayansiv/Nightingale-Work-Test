# Coherence, AI safety careers

A layer on top of existing AI safety job boards that answers a question they don't: given what you
believe about AI risk, which research agendas and policy levers should you be working on, and where
is the field thin?

Snapshot MVP. Data is pulled once, reviewed and committed. No database, no accounts, no server-side
state.

## Running it

```bash
npm install
npm run ingest    # data/raw/ + data/classification/  ->  data/derived/
npm run verify    # acceptance criteria + calibration; exits non-zero on failure
npm run dev
```

`npm run verify` is the gate before any commit. It checks the spec §18 acceptance criteria that
silently stop holding, the abstain-versus-unsure distinction is one `?? 0` away from being false
and nothing about the UI would look wrong if it broke, plus the coordinate-derivation calibration,
which caught two real sign errors on its first run.

## The three findings worth knowing

**1. Agenda coordinates are derived, not assigned.** The spec's riskiest dependency was whether
Shallow Review agenda pages carry a usable assumptions field. They do, on 59 of 74 agendas, drawn
from a **closed vocabulary of 12 canonical orthodox problems**. That turned ~1,258 hand judgements
into ~40, each with a written rationale that renders in-product next to the coordinate it produced.

**2. The field disagrees with itself by 3× about its own size.** Summing Shallow Review's per-agenda
FTE ranges gives 1,142–3,172. The independent AI Safety Field Growth Analysis 2025 gives 620–645.
Double-counting doesn't explain it (1.28 agendas per researcher). They measure different
populations. We publish both and add a **scale-invariant share column**, which is what neglectedness
arguments actually need. See OD-02.

**3. Classification without an API key is a feature here, not a compromise.** Roles are classified
by a committed rule table that names *the phrase it matched, in the role's own words*, auditable,
re-runnable, diffable. The cost is a **126-role review queue**, which is written to
`data/derived/review-queue.json` rather than hidden.

**Three real defects the calibration harness caught**, none of which would have shown up as a
visibly broken UI: seven inverted `patch_rebuild` signs in the derivation; Debate deriving as
interpretability-positive because it lists an assumption it *attacks*; and two question loadings
transcribed from the spec backwards, which routed anyone wanting formal guarantees away from
Guaranteed-Safe AI. `npm run verify` now scores synthetic respondents end to end so the last class
cannot recur silently.

## Layout

```
data/
  raw/              committed source pulls (Shallow Review, 80k board)
  config/           axes, questions, scales, derivation, calibration
  classification/   the hand-tagging: orgs.csv, signals.json, role-overrides.json
  seed/             policy levers, field-building categories, people roster
  content/          reading lists, caveats, disclaimers
  derived/          generated by `npm run ingest`, do not hand-edit
scripts/            ingest + verify
src/
  lib/              scoring, matching, permalink, data access
  components/       AxisPlot (the signature element), Provenance
  pages/            home, instrument (quiz), results, browse (roles), tables (agendas), agenda, axis
```

Adding or removing an axis or a question requires editing `data/config/` only. `npm run verify`
asserts no axis id is hard-coded outside the joint-risk formula, which is the spec's own exception.
